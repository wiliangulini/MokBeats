Plano de execução (corrigido e priorizado)

Fase 0 — Backend mínimo e dados de selects
- Backend como fonte de verdade para Gênero/Humor/Subgênero (mover dados estáticos do front para o Node).
- Endpoints novos/ajustados (simulados em memória):
  - GET /api/genres-full → objeto { genero: [subgêneros] }.
  - GET /api/generos → lista de gêneros (chaves de genres-full).
  - GET /api/subgeneros?genero=… → subgêneros por gênero.
  - GET /api/humores → lista de humores.
  - GET /api/tracks/latest-unique-by-producer?limit=N → últimas sem repetir produtor (baseado em id desc).
  - GET /api/config → dados de configuração (ex.: whatsapp).
- Manter endpoints atuais de músicas/playlists/favoritos.

Fase 1 — Validações de formulários (front)
- Login: adicionar Validators (email, required, minLength de senha) para cadastro, login e reset.
- Produtores: fortalecer validações (required/email) e corrigir select de Stems (control próprio). Preparar controles para gênero primário/secundário e humor (dados do backend).

Fase 2 — Produtores (dados dinâmicos + regras)
- Popular selects de “Gênero primário” e “Subgênero secundário (opcional)” a partir de /api/genres-full.
- Popular “Humor” a partir de /api/humores.
- Impedir múltiplas músicas: opção A (1 música sem stems) OU B (1 música + até 4 stems). Mensagem clara da regra.
- Preparar campos ISRC/UPC/HASH/OUTROS (placeholders dinâmicos + validações regex). ISRC e UPC obrigatórios.
- Uploads 15/30/60s com validação de duração (±200ms) no backend (próxima fase).

Fase 3 — Backend de upload e validações de negócio
- POST /api/producers/track: receber 1 música (sem stems) OU 1 música + até 4 stems; rejeitar casos fora da regra.
- Validar duração idêntica entre música completa e stems; validar loops 15/30/60s (±200ms).
- Validar ISRC/UPC/HASH no backend (middleware com regex definidas abaixo).

Fase 4 — Player (stems sincronizados + minimizar)
- Carregar stems pela API por id da track.
- Sincronizar play/pause/seek dos 4 stems com a faixa principal.
- Minimizar/Expandir: botão com ícone de áudio; manter reprodução ao minimizar; persistir estado.

Fase 5 — Home, Gênero e Humor (consumo real)
- Home Seção 2 (“Ouça nossos especialistas…”): consumir /api/tracks/latest-unique-by-producer.
- Gênero: lista usando /api/genres-full; busca filtra itens do gênero selecionado (debounce + query param).
- Humor: remover input de pesquisa.

Fase 6 — Rodapé e Preços
- Rodapé: link WhatsApp via /api/config (ou env); abrir em nova aba.
- Preços: ajustar layout — cards laterais menores e card central maior.

Fase 7 — Qualidade e release
- Testes unitários/integrados (validações, filtros, upload) e e2e (Produtor → upload → Player → Home).
- A11y (labels/aria) e pequenos ajustes de performance.
- Feature flags caso necessário (player novo, Home).

Regex e regras (reuso front/back)
- ISRC: ^[A-Za-z0-9]{12}$
- UPC-A: ^[0-9]{12}$ | UPC-E: ^[0-9]{6}$
- HASH (hex): MD5 32, SHA-1 40, SHA-256 64, SHA-512 128.
- WhatsApp (E.164): normalizar dígitos e montar https://wa.me/<E164>.
- Loops: 15/30/60s com tolerância (±200ms).
- Stems: 1–4 arquivos; duration_ms idêntica à faixa completa.

Observações
- Esta ordem prioriza tornar o backend a fonte dos dados dos selects (Gênero/Humor/Subgênero) e ativar as primeiras validações no front (Login/Produtores). As próximas fases alinham regras de upload, Player e páginas (Home/Gênero/Humor).
