## 13. Decisões técnicas tomadas

### Decisão 1: correção de bug em `resolve_node_bin` (start.sh)

**Decisão:** redirecionar as mensagens de erro para stderr.
**Justificativa:** em `VAR="$(resolve_node_bin ...)"`, mensagens em stdout ficam capturadas pela
substituição de comando e nunca chegam ao terminal quando o script sai por `set -e` — confirmado
com teste isolado antes/depois da correção.
**Alternativas consideradas:** manter em stdout e aceitar saída silenciosa.
**Trade-offs:** nenhum — é estritamente uma correção, sem custo.

### Decisão 2: ordem de execução B1 antes do smoke test completo de R1a

**Decisão:** instalar Node 24.18.1 e rodar a limpeza/reinstalação (`npm ci`) do backend antes do
smoke test fim a fim do `start.sh`.
**Justificativa:** o `node_modules` existente tinha o binário nativo do `bcrypt` compilado para
outro ABI; testar R1a isoladamente antes derrubaria o backend por um motivo alheio à lógica do
script de runtime.
**Trade-offs:** nenhum risco adicional — mesma sequência de comandos, ordem diferente.

### Decisão 3: dois commits distintos a partir de um `server/package.json` misto

**Decisão:** reconstruir temporariamente a versão intermediária do arquivo (`engines`/scripts de
R1a + `bcrypt ^5.1.1` ainda antigo) para o commit de R1a, depois restaurar `^6.0.0` para B1.
**Justificativa:** manter cada commit autoconsistente com seu próprio `package-lock.json`
(reversível e auditável isoladamente), sem usar `git add -p` (interativo, indisponível neste
ambiente).
**Trade-offs:** nenhum — resultado idêntico a two commits normais, só o processo de staging foi
manual.
